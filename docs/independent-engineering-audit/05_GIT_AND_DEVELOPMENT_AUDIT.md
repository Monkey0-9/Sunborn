Observations:
- Commit messages claim "complete" / "verified" states that the code does not fully support (e.g. "eliminate simulated shortcuts" while the frontend still ships a 698-LOC fake backend and defaults remain mocked). This is a **claim hygiene** problem, not a git problem.
- No release tags. `RELEASE_NOTES.md` exists but no `v*` tag; `release.yml` triggers on `v*.*.*` tags that were never cut.
- No branch protection evidence in-repo (`branch_protection.md` is documentation only and names checks that do not exist).

## 3. Working-tree hygiene

- `.gitignore` ignores `/target` but not `**/target/` → `fuzz/target/` can leak.
- Unignored on disk: `.mypy_cache/`, `.ruff_cache/`, `sbom.cyclonedx.json`, `research/results/baseline_backup/`.
- `*.png` is ignored, which hides committed-intent screenshots rather than deleting them.
- `.trunk/` is ignored wholesale, so `trunk.yaml` config cannot be committed.
- `frontend/pnpm-lock.yaml` is ignored even though the repo uses npm — dead rule.

## 5. Development process findings

- **No Dependabot / CodeQL / SECURITY.md / stale / funding** config.
- `branch_protection.md` lists required status checks (`verify-ci / test-workspace`, `verify-ci / frontend-test`, `verify-ci / openapi-drift`, …) that **do not match any job id** in `ci.yml`/`security.yml`. The documented protection would be unsatisfiable.
- `release.yml` builds and pushes images but has no cosign signing or SLSA attestation, despite docs claiming SLSA Level 3.
- `PULL_REQUEST_TEMPLATE.md` asks authors to declare invariant compliance "PASS", but nothing enforces it.

## 6. Verdict

Git hygiene is **MEDIUM**: history is intact and no secrets were found in tracked files during review, but several generated/duplicate artifacts are tracked, ignore rules are incomplete, release tags are absent, and the documented branch-protection contract is fictional.
